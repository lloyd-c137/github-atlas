# Project awareness and task management

## Brief the user

Inspect repository description/default branch, project guidance, recent meaningful changes, open work, assignments for the authenticated user, PRs awaiting review, unresolved feedback and CI/checks. Use exact links. Don't call an item “important” unless the project has a priority field or a human has said so; otherwise report it as open or recently changed. Distinguish “no items found” from “could not access.”

## Create or update work

1. Search Issues (including closed/recent ones where useful) and existing board entries for a duplicate. Compare intent, not only title text.
2. Preserve the user's facts. A useful Issue says context, goal, expected outcome and acceptance checks; unknown fields can be marked “to confirm.” Do not fabricate severity, dates, diagnosis, reproduction details or ownership.
3. Follow existing templates, types, labels, milestones and Projects workflow when available. If none exist, create no taxonomy or board without a request. Use an Issue as the default shared task record.
4. Assign to the user only when they asked to take it or assignment is clearly requested. Do not assign other people or change plans without human direction.
5. For progress/blockers, post only the user's intended update, in their voice without embellishment. Include relevant links and what is needed to unblock.
6. Verify the created/updated Issue, its assignee/labels/status, comments and board item if changed. Report the link and state.

For non-file work (research, product feedback, meeting notes, testing observations), use an Issue or project-approved artifact/comment. Never create an empty PR just to fit a workflow.
