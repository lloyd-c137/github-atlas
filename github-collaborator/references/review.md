# Review and feedback

1. Identify the exact PR and fetch its latest metadata, diff, linked task/acceptance criteria, review threads, checks, and current base/head state. If it changed during review, refresh before posting.
2. Inspect the full relevant changes. Prioritize actionable correctness, security, data-loss, regression and acceptance failures. For each finding, give a file/location, impact and concrete remedy. Separate required fixes from optional suggestions. Do not report style preference as a defect.
3. State which areas were inspected and checks observed, including pending or absent checks. Do not infer full correctness from green CI.
4. Present review findings to the user before posting when they have not explicitly asked to publish them. If asked to publish, use an ordinary review comment or a changes-requested review as appropriate. Never issue an approval for the user's review and never approve your own work.
5. Verify the posted review/comment and link it. When responding to received feedback, read the whole thread, implement or answer only the requested task, preserve context, and verify whether threads are resolved. Do not resolve another person's thread as a substitute for their acceptance.

AI findings are assistance, not a human approval or acceptance decision.
